# sync-retired-paths.txt — PERMANENT consumer-cleanup manifest
# =============================================================================
# WHAT THIS IS
#   One repo-relative path per line. On every sync, sync-to-project.sh reads
#   THIS FILE FROM THE SOURCE (claude-pattern) — .claude/scripts/ is excluded
#   from the rsync, so the consumer's copy is never the authority — and deletes
#   each listed path from the TARGET repo. It is how a file that claude-pattern
#   stopped shipping stops existing in every repo that already received it (the managed
#   fleet is 17, per .claude/repos.json; the pass also runs in any other local checkout).
#   Without it, deletions are invisible to a copy-only sync: the source drops a
#   file, every consumer keeps its stale copy forever.
#
# WHY IT IS PERMANENT (governance)
#   This file is NOT a one-run migration script. It is a standing `rm` capability
#   that executes UNATTENDED in every consumer repo (session-start auto-sync),
#   with no human reading the diff. A wrong line here is not a bug in one repo —
#   it is a supply-chain event across the whole fleet. Treat every edit as a
#   privileged change:
#     • Registered in .claude/commands/plan-w-team/shared/governance-tags.md, so
#       any diff touching this file forces a Step-5 security review.
#     • Every line is validated at RUNTIME by the 11-rule guard set in
#       sync-to-project.sh (rules 1-6 abort the WHOLE pass on any violation —
#       no partial deletions) and STATICALLY at source by a bats lint.
#     • `--dry-run` prints a per-path action log; that log is the reviewable
#       diff. Read it before a fleet sync.
#   Adding a line is a one-way door for the consumers that have already synced:
#   their rollback window is the ~2 retained .claude/agents.backup.<ts> dirs
#   (which now hold agents/ AND skills/) plus their own git history.
#
# WHAT MAY GO IN HERE (rule 5 — enforced at runtime AND by the static lint)
#   A line must either
#     (a) start with `.claude/agents/`, `.claude/skills/`, or
#         `.claude/agent-sets/` AND have at least one path segment after that
#         prefix (a bare prefix would sweep an entire shipped tree), or
#     (b) match the exact-path whitelist hardcoded in sync-to-project.sh for the
#         R13 legacy agent-config cluster and the two retired top-level
#         stragglers (7 top-level `.claude/*.md` docs + 2 scripts).
#   No absolute paths, no `~`, no `..` segment, no globs, no whitespace, no
#   quotes, no CRLF — the charset allowlist is `^[A-Za-z0-9._/-]+$`.
#
# WHAT MUST NEVER GO IN HERE
#   • Any path that is, or is an ancestor of, something the sync still ships —
#     any keep-tier agent, any `.claude/skills/<name>/` directory. Rule 6 aborts
#     the entire pass on such a line rather than trusting the author.
#   • Any CONSUMER-AUTHORED path (parts: `.claude/skills/audit/`,
#     `.claude/skills/cobe-assistant/`). Read this one carefully, because an
#     earlier version of this header got it backwards: rule 6 does NOT protect
#     these. Rule 6 only knows what the SOURCE ships, and a consumer-authored
#     skill is by definition absent from the source tree — so it is in neither
#     the profile set nor the source skills set, and rule 6 has nothing to
#     collide with. Rule 7 is silent for exactly the same reason. The controls
#     that actually hold here are, in full: MANIFEST CONTENT (this list is the
#     control — never write such a path into it) + GOVERNANCE REVIEW (this file
#     is registered in shared/governance-tags.md, so any diff forces a Step-5
#     security review) + STATIC LINT (a bats case greps this manifest for known
#     consumer-owned trees and fails the suite if one is named). All three are
#     procedural. There is no structural backstop — which is precisely why the
#     false claim mattered: a reviewer who believed it would see no gap to fill.
#   • A path still present in the SOURCE tree. Rule 7 re-checks this at runtime
#     and SKIPS (never deletes) such a line — a retired path that still exists
#     upstream means the manifest is ahead of reality, which is a fail-safe skip,
#     not a deletion.
#   • Anything under `.claude/scripts/` other than the two whitelisted legacy
#     scripts. Consumer- and operator-authored scripts live there.
#
# TRAILING-SLASH / ORDER CONVENTION
#   Directories are written WITHOUT a trailing slash (the reader strips EVERY
#   trailing slash, to a fixed point, and never appends one to an `rm` argument —
#   a trailing slash on a symlinked dir is what turns "remove the link" into
#   "remove the contents"). Stripping only ONE was finding C1: `<path>//`
#   normalised to `<path>/`, which string-matched no shipped path and so slipped
#   past both arms of rule 6.
#   Children are listed BEFORE their parent directory so the per-path action log
#   reads as an explicit inventory rather than one opaque tree sweep.
#
# PROVENANCE
#   Authored by the agent-roster restructure (spec:
#   docs/specs/restructure-the-claude-agents-roster-per-anthropic-s-current-
#   subagents-vs-skills-d6f25286.md — Classification/Disposition Tables are
#   ground truth for every row below).
# =============================================================================
